# Workshop execution

Use this for a bounded asset job admitted under
[[specs/admission and feedback.spec]]. Detailed asset briefs and proprietary art
remain in their owning project. This fork hosts only the generic procedure.

1. Read the brief, target scale/style and acceptance criteria. Locate an existing
   related asset/generator before producing a duplicate. Record a source revision.
2. Collect a small relevant reference set for shape/material/construction questions.
   Save provenance and rights; inspiration images are not automatically shippable.
   Optional concept art is a separate capability/budget, not assumed from Codex login.
3. Use Blender CLI and editable Python construction to build or revise the asset.
   Retain parameterized dimensions, materials and the best known .blend/source.
4. Render comparable multi-view previews. Critique silhouette, joints, scale,
   contact geometry and consistency with the brief. Revise within the admitted
   budget and bounded attempts; plateau/failure becomes a checkpoint, not an
   endless self-improvement loop.
5. For moving rigid parts, preserve pivots and provide a short named action/clip.
   Organic creatures need topology, skinning and deformation review; do not call
   a nice still image an animation-ready model. Keep fantasy work waiting for its
   actual brief. Start with practical objects and decorations, not whole game systems.
6. Package editable source, generator, materials/textures, appropriate export,
   preview and result manifest. Label artifact states precisely: generated,
   visually reviewed, engine-qualified, owner-approved. Only claim checks performed.
7. Route Unity qualification to the owning project's official CLI workflow with
   exclusive Editor ownership. No blind launch, second Editor, scene replacement
   or desktop takeover. Software tests require explicit authorization. Human VR
   comfort/reach is not inferred from a desktop render. Offline asset work does
   not itself authorize live HQ installation.
8. Publish results to private artifact storage and the future Hub gallery. Bind
   feedback to the exact revision. Requested changes resume retained source;
   accepted models enter the reusable catalogue. Human review can be batched and
   must not be required at every internal stage.

The useful pattern is editable Blender code plus visual feedback, as explored by
[LL3M](https://arxiv.org/html/2508.08228v1), followed by conventional export,
rigging and action workflows. This is not a claim that its research quality or
multi-agent architecture transfers automatically to production assets.

No asset production has been run by this bootstrap. See
